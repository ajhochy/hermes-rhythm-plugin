## Installed Desktop route diagnosis and repair

- Parent opened the installed Hermes Desktop v0.20.5, enabled Rhythm, and observed exactly one sidebar row. The route changed to `#/rhythm`, but the page error boundary rendered the generic new-chat composer. The built-in Capabilities route rendered normally. Two Desktop rescans did not duplicate Rhythm and did not repair its page.
- The first Desktop renderer stack contained `TypeError: gX is not a function` in the packaged route. The bundle imported `jsx` from `react/jsx-runtime`; the installed host's runtime shim did not provide a callable JSX function. A VM probe reproduced the failure with that host shape. The packager now binds bundled JSX to the host's React `createElement` and retains `react` as an external singleton. The probe and packaging file passed. After replacing the package while the Desktop Rhythm toggle was off, the JSX error disappeared.
- A second renderer stack then contained `TypeError: Cannot read properties of undefined (reading 'get')` at the first `useValue(host.state.profile)` call. Read-only inspection of the installed release renderer and parent DevTools probe confirmed that `profile`, `connectionId`, and `gateway` each exist as host state atoms with callable `get` and `subscribe`; reads returned string types without disclosing values. The installed SDK's `useValue` wrapper has the expected `useStore(atom)` signature. Its failure cause remains unknown.
- A candidate change replaced those three calls with host React's `useSyncExternalStore`; a VM test modeled an SDK hook that always throws the observed error and passed with the candidate. That synthetic hook did not match the verified installed implementation, and native render could not be observed after installing the candidate because the host never mounted the route. The candidate source change and synthetic test were therefore removed. The final source retains the SDK `useValue` calls and ships only the observed JSX runtime repair.
- The candidate package `dist/rhythm-feature-pack-mega-host-state-fix` built and validated; its `desktop/dist/rhythm.mjs` SHA-256 matched the then-installed `~/.hermes/desktop-plugins/rhythm/plugin.js` (`7db8443dffed525a9f242ce23ec2dff1f1a1bf4cec8e842e4aabf616f068cc3d`). The installer exited 0 with config/auth unchanged. `hermes plugins doctor rhythm --ci` exited 0 with three tools and zero hooks. This package was used only for the diagnostic live attempt and is not the final artifact.
- After Desktop toggle ON and Rescan, the parent still saw the generic composer at `#/rhythm`. The last Desktop log write and last Rhythm exception were at 22:44 PDT, before this package replacement; no fresh exception proved that the new bundle rendered. An in-window reload was used to clear the existing error boundary and loaded plugin module without quitting Desktop. It initiated the installed host's sequential multi-profile backend bootstrap and showed `Loading session`. The log recorded 17 backend READY events by 23:06:40 PDT, then began revisiting earlier profiles and evicting idle backends under the host's LRU cap 3. The route remains unverified while the host is in this loading state; no new Rhythm renderer exception appeared in the file log.
- Native UI later cleared `Loading session` after Show all profiles was turned off, but `#/rhythm` still showed the generic Hermes new-chat composer. The parent restored Show all profiles to its original state. No message was sent and DevTools Console had no current error or warning.
- A read-only live registry probe of the installed route module returned exactly one `{key:'plugin:rhythm:rhythm:page', path:'/rhythm', title:'Rhythm'}`. Function fingerprints on `route.render().type` gave `newHook:true`, `oldHook:false`, `hasWorkspace:true`, proving the candidate package was loaded. M3 connection UI, read-only hosted sample, unsent draft, and duplicate reload assertions cannot be claimed while the native page is absent. This is an installed-host presentation blocker; the final source retains only the JSX repair with a native-observed error and a focused regression probe.
