## Decisions

- No public client ID was guessed or copied into source. Missing/invalid profile configuration fails OAuth start before issuing state. The parent owns setting the public ID and the live browser flow; this run did not read or write credentials.
- The deployed desktop exchange writes integration credentials and therefore cannot serve plugin login. The plugin now requires `GET /auth/google/desktop-login-capability` to return a literal `loginOnlyDesktopExchange: true` before issuing OAuth state, then uses only `POST /auth/google/desktop-login-exchange`. A 404, false or malformed capability maps to recoverable HTTP 503 and no browser URL. The Rhythm API agent implemented the matching additive paths locally with 8/8 focused tests and a TypeScript build; production has not deployed them. Do not retry hosted OAuth until deployed and verified.
- The plugin retains one pinned hosted origin, no redirects, and the existing PKCE/state/profile/loopback checks. `/tasks` accepts at most 500 objects and a 1 MiB response; the dashboard accepts at most 128 KiB. The task list emits at most 512 KiB, trims list notes to 1,024 characters, and leaves task detail bounded at 8,192 characters. Other calls retain the 32 KiB cap.
- A fixed source or isolated dev shell is not an installed-host qualification. The installed release cannot acquire the fork host changes without a rebuild/relaunch, which is outside this agent's ownership and prohibited for the running app. Switching active profile away/back may remount the route table in the installed release but is only a workaround hypothesis, not fixed-host proof. Closing/reopening Settings was observed by the parent **not** to remove the stale backend plugin row.
- Parent-owned fixed candidate qualified running backend disposal without credentials: disable the Desktop Rhythm toggle, remove only the two scratch installation roots, then Rescan. Agent plugin inventory fell from one to zero and the Rhythm sidebar disappeared in the same live host/backend. The prior renderer still showed a shadowed disk-copy row until host reload. On final candidate replay, the repaired Rescan also removed that stale Desktop row while preserving the bundled Rhythm record in the OFF state and Agent plugins at zero, with no restart during removal (parent screenshots 27–31).
- `apps/desktop/README.md` documents `npm run dev`; `electron/main.ts` independently honors `HERMES_DESKTOP_USER_DATA_DIR`, `HERMES_HOME`, `HERMES_DESKTOP_APP_NAME`, and `HERMES_DESKTOP_HERMES_ROOT`. A parent-owned candidate with fresh scratch values for all four can test mount/disposal without touching the installed profile. That candidate has no live Rhythm credential unless the parent explicitly sets it up. This macOS checkout's `scripts/dev-sandbox.sh` uses Linux namespaces and is not the macOS launch path.
